# cc-monitor 使用手册

cc-monitor 让你在局域网内用手机查看并操控本机正在运行的 Claude Code 会话。手机上有两种视图：聊天视图适合读回答、发 prompt；终端画面和电脑上的终端一模一样，适合处理权限确认、按 Esc、用斜杠命令。所有数据只在你的局域网内流动，不经过任何外部服务器。

## 1. 工作原理，先知道这几件事

- Claude Code 自带后台会话功能：用 `claude --bg` 启动的会话由它自己的守护进程托管，终端关了也不会退出，随时可以用 `claude attach` 接回来。
- cc-monitor 就是那个"接回来"的客户端。它接上会话，把画面复制给手机和电脑上的多个页面，把你在页面上的输入送回会话。
- 一个后台会话同一时刻只能被一个客户端接住。所以电脑上也请通过 cc-monitor 看会话，不要直接运行 `claude attach`。直接运行会把 cc-monitor 挤下去，手机页面会提示"已被本地窗口接管"，点"接管回来"就能抢回。
- 普通方式启动的会话（直接敲 `claude`）不能被接管，手机上只能看它的状态和对话记录，不能输入。

## 2. 准备工作

### 环境要求

- Windows 10 或 11，Node.js 24 或更新。
- 已安装并登录 Claude Code，命令行能运行 `claude --version`。cc-monitor 会自动找到 npm 方式安装的 `claude.exe`。
- 手机和电脑在同一个局域网。

### 安装

在项目目录里执行：

    npm install
    npm run build -w web

第二条命令构建手机页面，只需要在首次安装和更新代码后执行。

### 放行防火墙

Windows 默认会拦截来自局域网的连接。用管理员身份打开 PowerShell，执行一次：

    netsh advfirewall firewall add rule name="cc-monitor" dir=in action=allow protocol=TCP localport=8787

如果你改过端口，把 8787 换成你的端口。

## 3. 启动与连接

### 启动监测器

    npm start

终端会打印三样东西：

1. 配置文件位置，默认在 `%LOCALAPPDATA%\cc-monitor\config.json`。
2. 一个或多个带访问口令的地址，形如 `http://192.168.1.8:8787/?t=口令`。有多块网卡时会打印多行，手机用的通常是 192.168 开头的那个。
3. 第一个地址的二维码，以及一段可以粘贴进 Claude Code 设置的 hooks 配置（见第 6 节）。

口令在首次启动时随机生成并保存在配置文件里，之后每次启动都一样。拿到口令就等于拿到你这台电脑的终端，不要截图外传，不要把地址发到群里。

### 启动要监控的会话

在你的项目目录里：

    claude --bg --name 项目名

`--name` 可省略，但起个名字在手机列表里更好认。命令会立刻返回并打印一个 8 位短 id，会话在后台继续运行。

### 手机打开

用手机相机或浏览器扫终端里的二维码，或者直接输入带口令的完整地址。首次访问成功后口令会记在这个浏览器里，地址栏里的 `?t=` 会自动去掉，之后打开 `http://192.168.1.8:8787/` 就行。

cookie 是按浏览器记的：如果相机扫码后是在相机自带的内置浏览器里打开的，你平时用的浏览器并没有口令，请用平时的浏览器扫码或粘贴完整链接。

没带口令直接打开地址时，页面会提示你去扫码，不会出错。

### 电脑浏览器打开

电脑上同样可以用，本机访问更简单：打开 `http://127.0.0.1:8787/?t=口令`，或者用局域网地址 `http://192.168.1.8:8787/?t=口令`。同样是第一次带口令，之后在这个浏览器里直接打开地址即可。

## 4. 手机页面怎么用

### 会话列表

首页列出本机所有正在运行的 Claude Code 会话，最新的在上面。每一行显示：

- 状态点：绿色是空闲，橙色是忙碌。
- 名称：你用 `--name` 起的名字，没起名则显示 Claude Code 自动起的名字。
- "只读"标记：不是用 `--bg` 启动的会话，只能看不能输入。
- 工作目录。

列表会自动刷新，新会话几秒内出现，退出的会话几秒内消失。

### 会话页：状态栏

进入会话后最上面是状态栏，依次可能出现：

| 显示 | 含义 |
| --- | --- |
| 已连接 | cc-monitor 已接上这个会话，可以输入 |
| 连接中 | 正在接入，稍等 |
| 已被本地窗口接管 | 有人在电脑上直接运行了 `claude attach`，旁边有"接管回来"按钮 |
| attach 进程退出，退出码 … | 接入失败，后面是原因，常见于会话已经停止；也有"接管回来"按钮可重试 |
| 只能查看，不能输入 | 这个会话不是用 `--bg` 启动的 |
| 忙碌 / 空闲 | 会话此刻是否在生成回答 |
| 80×24 这样的数字 | 当前终端画面的列数和行数 |
| 网络断开，重连中 | 手机和电脑之间的连接断了，会自动重连 |
| 转录格式可能已变化 | Claude Code 升级改了对话记录格式，聊天视图可能不完整，终端画面不受影响 |

### 聊天标签

默认打开的就是聊天标签，适合手机阅读：

- 你发的 prompt 靠右，Claude 的回答靠左。
- "思考"、"调用 某工具"、"工具结果"默认折叠，点开可看详情。
- 新消息自动滚到底部；你往上翻看旧消息时不会被打断，翻回底部后恢复自动滚动。
- 会话刚启动还没发过 prompt 时，这里是空的，这是正常的。

底部输入框发 prompt：

- 支持多行，直接换行即可，整段作为一条 prompt 发出，不会被拆成多条。
- 点"发送"或按 Ctrl+Enter 发送。
- 发送成功后输入框清空。如果此刻网络断了，输入框会保留你的文字并提示"网络未连接，内容已保留"，等重连后再发。
- 会话处于只读、未连接或网络断开时，输入框是灰色的。

### 终端标签

点"终端"切到和电脑上一样的画面。会话刚打开的头一两秒，输入会稍有延迟，之后正常。

- 画面上方一排快捷键：Esc、Ctrl+C、Tab、Shift+Tab、四个方向键、Enter。Claude Code 弹出权限确认时，用方向键和 Enter 选择；想打断正在生成的回答按 Esc；Shift+Tab 切换权限模式。
- 直接点画面也能用手机键盘打字，但手机输入法的联想和自动纠错不太可靠，建议 prompt 还是用底部输入框发，终端里只做按键操作。
- 画面按手机的实际宽度排版，Claude Code 会自己适应窄终端。你在手机上操作期间，电脑上的同一画面会跟着变窄；回到电脑碰一下键盘或拖一下窗口就恢复。

### 多台设备同时看

同一个会话可以同时在多个页面上打开，画面同步，谁都能输入。画面尺寸跟随最近在终端标签里操作的那台设备。

## 5. 电脑上查看同一个会话

不要直接运行 `claude attach`。用 cc-monitor 提供的命令，在项目目录里：

    npm run attach -- 项目名

也可以用短 id 代替名字。之后这个终端窗口里就是会话的画面，可以正常打字。按 Ctrl+] 或 Ctrl+Z 退出，退出只关掉这个窗口，会话和手机页面都不受影响。

如果你忘了，直接运行了 `claude attach`，手机状态栏会变成"已被本地窗口接管"。想让手机继续用，在手机上点"接管回来"，电脑上的那个窗口会退出并打印 Session opened in another window。

### 在手机上停止会话

会话页状态栏右侧有 `[停止会话]`。点一下它会变成"再点一次确认停止"，几秒内再点一次才真的停止，防止误触。停止相当于在电脑上运行 `claude stop`：会话从列表里消失，对话记录保留，之后可以在电脑上用 `claude --bg --resume 会话id` 继续。手机上不提供删除，删除仍在电脑上用 `claude rm`。

只读会话没有这个按钮，它不是后台会话，只能在它自己的终端里关闭。

## 6. 手机提醒

把启动日志里打印的那段 hooks 配置合并进 `%USERPROFILE%\.claude\settings.json`。它长这样：

    {
      "hooks": {
        "PermissionRequest": [{ "hooks": [{ "type": "http", "url": "http://127.0.0.1:8787/api/hook", "timeout": 5 }] }],
        "Notification":      [{ "hooks": [{ "type": "http", "url": "http://127.0.0.1:8787/api/hook", "timeout": 5 }] }],
        "Stop":              [{ "hooks": [{ "type": "http", "url": "http://127.0.0.1:8787/api/hook", "timeout": 5 }] }]
      }
    }

如果 settings.json 里已经有 hooks，把这三个事件加进去即可。cc-monitor 不会替你改这个文件。

配好之后，手机页面会在这些时刻出现横幅：

- Claude Code 需要你确认权限时：提示切到终端标签处理。
- Claude Code 等你输入时："CC 在等你输入"。
- 一轮回答结束时："这轮结束了"，几秒后自动消失。

点横幅可以关掉它。没有配 hooks 一切照常，只是没有这些提醒。

## 7. 配置

配置文件 `%LOCALAPPDATA%\cc-monitor\config.json`，改完重启监测器生效：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| port | 8787 | 监听端口，改了记得同步改防火墙规则和 hooks 里的端口 |
| bind | 0.0.0.0 | 监听地址，默认所有网卡 |
| token | 自动生成 | 访问口令，32 位十六进制；删掉这个字段重启会生成新的 |
| minCols | 40 | 终端画面最少列数 |
| minRows | 24 | 终端画面最少行数 |
| idleDetachMinutes | 10 | 所有页面都关掉多少分钟后，监测器主动从会话上脱离；再打开页面会自动接回 |
| ringBufferKB | 512 | 新打开的页面能回放多少最近画面 |
| claudeExe | 自动查找 | 找不到时手动填 claude.exe 的完整路径 |

环境变量 `CCM_PORT` 和 `CCM_BIND` 优先级高于配置文件，适合临时换端口：

    set CCM_PORT=9000 && npm start

## 8. 会话管理命令速查

这些都是 Claude Code 自己的命令，cc-monitor 不替你管会话的生死：

| 命令 | 作用 |
| --- | --- |
| `claude --bg --name 名字` | 在当前目录启动一个后台会话 |
| `claude agents` | 列出所有会话 |
| `claude logs 短id` | 看某个后台会话最近的终端输出 |
| `claude stop 短id` | 停止后台会话，对话记录保留，可用 `claude --resume` 继续 |
| `claude rm 短id` | 删除后台会话 |
| `claude --bg --resume 会话id` | 把一个旧对话在后台重新跑起来 |

会话停止后它会从手机列表里消失。手机上也可以停止，见第 5 节。

## 9. 排查

| 现象 | 原因与处理 |
| --- | --- |
| 手机打不开页面 | 先在电脑浏览器打开带口令的地址确认服务在跑；再检查防火墙是否放行、手机是否连在同一个 Wi-Fi、地址用的是不是电脑的局域网 IP（有多块网卡时换一个试） |
| 页面提示"需要访问口令" | 这个浏览器还没记住口令。扫一次终端里的二维码，或打开带 `?t=` 的完整链接；接口返回 unauthorized 也是同一原因 |
| 启动时报找不到 claude.exe | 在配置文件里把 claudeExe 填成完整路径，npm 方式安装通常在 `%APPDATA%\npm\node_modules\@anthropic-ai\claude-code\bin\claude.exe` |
| 启动时报端口被占用 | 换端口：改配置文件的 port，或用 `CCM_PORT` |
| 列表里没有会话 | 会话是否真的在跑，用 `claude agents` 核对；会话退出后几秒内会从列表消失 |
| 会话有"只读"标记，不能输入 | 它不是用 `--bg` 启动的。在它的目录里用 `claude --bg --resume 会话id` 重新跑起来即可接管 |
| 状态栏显示"已被本地窗口接管" | 电脑上直接运行了 `claude attach`。点"接管回来"，以后电脑上用 `npm run attach -- 名字` |
| 状态栏显示 attach 进程退出 | 会话可能已经停止，用 `claude agents` 核对；也可能守护进程异常，重新 `claude --bg` 一个会话 |
| 聊天标签一直是空的 | 会话还没发过 prompt；或者对话记录格式变了（状态栏会有提示），切终端标签看 |
| 终端画面显示不全 | 横屏能多显示一些；长回答在聊天标签里读更舒服 |
| 发送后输入框没清空 | 提示"内容已保留"说明网络断了，等状态栏的"重连中"消失后再点发送 |
| 刚打开终端标签时按键没反应 | 接入后的头一两秒输入会排队，稍等即可，不会丢 |

## 10. 安全与限制

- 口令等同于你电脑上的终端权限。只在可信的家庭或办公室局域网里用，不要把端口映射到公网，不要在公共 Wi-Fi 下使用。
- 传输是明文 HTTP。
- 同一会话同一时刻只有一个真正的接入方，cc-monitor 占着这个位置，所以电脑上也走 cc-monitor。
- 聊天视图依赖 Claude Code 的对话记录文件格式，官方声明该格式会随版本变化。格式变了终端画面照常可用，聊天视图可能缺内容。
- 手机上直接在终端里用输入法打中文不可靠，中文 prompt 请用底部输入框。
